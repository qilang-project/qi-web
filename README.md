# Qi Web

Qi Web 是一个用 **奇语（Qi）**编写的 Web 框架。性能上实测 **~122k RPS**（比 Express 快 5.5×，比 Node.js 快 ~25%），热路径用 Rust 加速。方向很明确：

- **核心像 Axum / Gin**
- **使用体验尽量像 FastAPI / Express**
- **控制器只是上层扩展，不是内核**

> 📘 AI 辅助：本项目带 [`SKILL.md`](SKILL.md)，可作为 agent skill 安装，让 AI 助手准确生成 qi-web 代码。

现在公开的重心就是这几个词：

- `路由`
- `handler`
- `request / response`
- `middleware`
- `session`
- `auth`

## 推荐写法

```qi
包 主程序;

导入 Web::{应用, 请求, 响应, 上下文};
导入 Web::{创建应用, 获取, 提交, 创建请求, 处理请求};
导入 Web::{路径参数, 文本, JSON, 输出响应};

函数 首页处理(上下文值: 上下文) : 响应 {
    返回 文本("你好，Qi Web");
}

函数 用户详情处理(上下文值: 上下文) : 响应 {
    变量 用户标识: 字符串 = 路径参数(上下文值, "id");
    返回 JSON("{\"id\":\"" + 用户标识 + "\"}");
}

函数 入口() {
    变量 应用值: 应用 = 创建应用();
    应用值 = 获取(应用值, "/", 首页处理);
    应用值 = 获取(应用值, "/users/{id}", 用户详情处理);

    变量 请求值: 请求 = 创建请求("GET", "/users/7", "", "");
    变量 响应值: 响应 = 处理请求(应用值, 请求值);
    打印行(输出响应(应用值, 响应值));
}
```

## 中间件

现在推荐把中间件写成这一种形状：

```qi
函数 请求标记中间件(下一步: 函数(上下文): 响应, 上下文值: 上下文) : 响应 {
    变量 响应值: 响应 = 下一步(上下文值);
    返回 设置响应头(响应值, "X-Request-Id", "qi-45");
}
```

注册方式：

```qi
变量 应用值: 应用 = 创建应用();
应用值 = 使用中间件(应用值, 请求标记中间件);
```

这里的 `下一步` 就是“继续往后走”的处理器。  
你可以在它前后做日志、鉴权、限流、补响应头，也可以直接提前返回响应。

现在已经内置了一组更接近 Fiber 习惯的中间件入口：

- `使用恢复(应用值)`
- `使用请求标识(应用值)`
- `使用响应时间(应用值)`
- `使用安全头(应用值)`
- `使用超时(应用值, 毫秒数)`
- `使用限流(应用值, 最大次数, 窗口毫秒)`
- `使用密钥认证(应用值, 头名, 密钥值)`
- `使用基础认证(应用值, 凭证文本)`
- `使用静态资源(应用值, 前缀, 目录)`
- `使用开发中间件(应用值)`
- `使用生产中间件(应用值)`

### 跨域 / 缓存 / 压缩

完整的 CORS / Cache-Control / gzip 三件套：

- `使用跨域开放(应用值)` — `*` 通配，常用 method/header 默认 600s 预检缓存
- `使用跨域配置(应用值, 允许来源, 允许方法, 允许头, 允许凭证, 最大缓存秒)`
  - 允许来源支持 `"*"`、单一来源、`","` 分隔的白名单
  - 自动处理 OPTIONS preflight，响应附 `Access-Control-Allow-*` + `Vary: Origin`
- `使用跨域暴露头(应用值, 暴露头)` — 设置 `Access-Control-Expose-Headers`
- `使用缓存(应用值, 指令文本)` — 例如 `"public, max-age=60"`，默认只对 GET/HEAD 生效
- `使用静态缓存(应用值, 秒数)` — `public, max-age=N` 的简写
- `使用不缓存(应用值)` — `no-store, no-cache, must-revalidate`，覆盖所有方法
- `使用压缩(应用值)` — gzip body，默认阈值 1024 字节
- `使用压缩配置(应用值, 最小字节)` — 自定义压缩阈值

注意：

- 压缩中间件应该 **最先注册**（最外层），让它能拿到经过其他中间件后的最终响应再 gzip
- 压缩只对 `text/*`、`application/json`、`application/xml`、`application/javascript`、`image/svg+xml` 等可压缩类型生效
- 压缩绕过常规序列化，直接把 headers + 压缩字节写到 socket，业务侧的 `响应.主体` 是 UTF-8 字符串这个限制不影响它

完整示例：`examples/CORS_压缩_缓存.qi`

`使用开发中间件` 现在默认会串上：

- `恢复`
- `请求标识`
- `响应时间`
- `跨域`

如果你要日志，单独追加 `使用日志(应用值)` 更稳。

`恢复中间件` 现在已经能拦住 **显式 `抛出`**，并把它转成 `500 Internal Server Error`。  
这条链是：

- `抛出 "boom"`
- 运行时安全调用边界
- `恢复中间件`
- `500` JSON 响应

当前还没有做到“拦住所有底层崩溃或非法内存访问”，但 Qi Web 这条应用层 recover 已经不是空壳了。

静态资源现在已经可以和开发中间件稳定叠加，前后顺序都能工作。

## Ctx

现在 `Ctx` 不只是参数提取器，也可以直接作为 handler 里的主工作台：

```qi
函数 状态处理(上下文值: 上下文) : 响应 {
    变量 请求标识文本: 字符串 = 请求标识(上下文值);
    变量 剩余超时: 整数 = 剩余超时毫秒(上下文值);
    变量 本地请求标识: 字符串 = 本地值(上下文值, "request_id");
    返回 返回JSON(
        上下文值,
        "{\"requestId\":\"" + 请求标识文本 + "\",\"local\":\"" + 本地请求标识 +
        "\",\"remaining\":" + 整数转字符串(剩余超时) + "}"
    );
}
```

常用入口：

- 请求读取：`参数 / 查询值 / 头值 / 原始主体 / 请求对象`
- 类型化提取：`参数整数 / 查询整数 / 表单整数`
- 状态信息：`请求标识 / 已耗时毫秒 / 剩余超时毫秒`
- 本地存储：`设置本地值 / 本地值 / 设置本地整数 / 本地整数`
- 直接返回：`返回文本 / 返回HTML / 返回JSON / 返回重定向 / 返回未找到`

## 事件流（SSE）

`事件流.qi` 在 chunked 流式机制之上提供 Server-Sent Events。适合 LLM token
渐显、进度推送、日志尾随等单向推送场景（浏览器端用原生 `EventSource`）。

```qi
函数 推送处理(上下文值: 上下文) : 响应 {
    SSE开始(上下文值);                        // 写 text/event-stream 响应头
    SSE发送(上下文值, "message", "第一条");    // event: message\ndata: 第一条\n\n
    SSE发送数据(上下文值, "无事件名，走默认 message");
    SSE发送(上下文值, "done", "[完成]");       // 结束事件，前端收到后 es.close()
    SSE结束(上下文值);                        // chunked 终止块
    返回 SSE完成响应();                       // 状态码 0 = 已自行写完
}
```

- 数据里的换行自动按规范拆成多条 `data:` 行，接收端会拼回。
- 依赖 `ctx.客户端句柄`，**必须用同步 `运行应用`**（`运行应用_异步` 不支持流式）。
- 连接在 `SSE结束` 后关闭；`EventSource` 默认会自动重连重放，一次性流务必发
  结束事件让前端主动 `close()`。
- LLM 流式聊天完整示例见 `examples/llm_聊天_SSE.qi`（有 QI_LLM_KEY 走
  qi-harness `流式问` 真 token 流，无 key 降级为固定回复逐字推送）。

## 实时页面（LiveView 式）

`实时页面.qi` 提供 Phoenix LiveView 式的服务端驱动 UI：状态在服务端，事件经
WebSocket 上行，服务端重渲染后 **DOM morph 局部 patch** 下行——客户端把新旧
DOM 树逐节点对齐，只改有差异的属性/文本/节点，焦点、光标、滚动、CSS 过渡天然
保住。页面上不用写一行业务 JS。

```qi
函数 初始状态() : 整数 {                       // 每连接一份状态（J 对象句柄）
    变量 状态: 整数 = J.创建对象();
    J.设置整数(状态, "计数", 0);
    返回 状态;
}
函数 渲染(状态: 整数) : 字符串 {               // 状态 → HTML 片段
    返回 "<h2>计数: " + 整数转字符串(J.获取整数(状态, "计数")) + "</h2>"
        + "<button data-click=\"加一\">+1</button>"
        + "<button data-click=\"加步\" data-value-step-size=\"5\">+5</button>";
}
函数 处理事件(状态: 整数, 事件名: 字符串, 载荷JSON: 字符串) : 整数 {
    如果 (字符串::等于(事件名, "加一") == 1) {
        J.设置整数(状态, "计数", J.获取整数(状态, "计数") + 1);
        // 服务端指令：渲染帧之后自动下发（对标 push_event / push_navigate）
        实时指令(状态, 指令_标题("计数变了"));
    }
    返回 状态;
}

应用值 = 实时路由_无鉴权(应用值, "/", 初始状态, 渲染, 处理事件);   // 公开页面
// 要按登录态放行用 实时路由带准入(…, 订阅载荷, 准入, 初始状态, 渲染, 处理事件)
运行应用(应用值);   // 依赖 WS 升级，必须用同步 运行应用
```

声明式绑定（对标 Phoenix 绑定，事件委托，morph 后无需重绑）：

**属性名一律用英文**——属性名虽然允许中文，但 CSS 选择器、devtools、前端工具链
对非 ASCII 属性名都不友好。事件名本身是业务字符串，中文没问题
（`data-click="投票"`）。

| 属性 | 触发 | 载荷 | 对标 |
| --- | --- | --- | --- |
| `data-click="事件"` | click | `data-value-*` | `phx-click` |
| `data-input="事件"` + `data-debounce="300"` | input（可防抖） | `{value}` + `data-value-*` | `phx-change` + `phx-debounce` |
| `data-keyup="事件"` + `data-key-filter="Enter"` + `data-clear-on-key` | keyup（可过滤键 / 触发后清空输入框） | `{key,value}` + `data-value-*` | `phx-keyup` |
| `data-submit="事件"` | 表单 submit | 字段名值对 + `data-value-*` | `phx-submit` |
| `data-confirm="要删吗？"` | —— 先弹确认框才上行 | | `data-confirm` |
| `data-value-xxx="v"` | —— 事件参数并入载荷 | | `phx-value-*` |
| `data-key="k"` | —— morph 列表对齐键 | | keyed comprehension |
| `data-ignore` | —— morph 跳过该子树 | | `phx-update="ignore"` |

属性名会被浏览器小写化，所以多词参数写 kebab：`data-value-card-id` 上行时
还原成 `cardId`。写成 `data-value-cardId` 会**静默失效**（浏览器存成
`data-value-cardid`，服务端按 `cardId` 取就是空串，没有任何报错）。

服务端指令（事件处理里 `实时指令(状态, 指令_*)`，渲染帧后自动下发）：
`指令_跳转(url)`、`指令_标题(文本)`、`指令_滚动(选择器)`、
`指令_事件(名称, 载荷JSON)`（window 上派发 `CustomEvent "qi:名称"`，页面 JS 可监听）。

- 内嵌 JS 运行时自动连 `路径 + "/ws"`；断线指数退避重连（0.5s 起 8s 封顶），
  重连后自动恢复服务端状态；断线期间 `<body>` 带 class `qi-offline`（并派发
  `qi:offline`/`qi:online` 事件）；触发事件的元素等待回帧期间带 class `qi-loading`。
- 渲染用户输入前先过 `转义HTML(文本)` 防注入。
- 完整示例见 `examples/实时_计数器.qi`（计数 + 防抖回显 + keyed 待办 + 标题指令）。

### 实时消息（定时器 / 后台任务 / 服务端主动推）

`实时消息.qi` 补上 Phoenix 的 `handle_info` + `Process.send_after` + `start_async`：
连接循环不再死等客户端事件，而是「等一小会儿客户端 → 抽干邮箱 → 再等一小会儿」。
于是两类以前做不了的事成立了——**没人点也要动的页面**（时钟、倒计时、进度轮询），
以及**慢活儿**（点一下要问 AI 三秒，页面必须立刻显示「思考中…」而不是卡住）。

用户函数从三个变四个，新增的 `消息处理函数` 与 `事件处理函数` 签名一模一样：

```qi
应用值 = 实时路由带消息(应用值, "/clock", 初始状态, 渲染, 处理事件, 处理消息);
// 块渲染版：实时块路由带消息(…, 块渲染函数, …)（多一层结构化 diff）
// 只挂 WS、页面外壳自己写：实时WS路由带消息(…)

函数 处理事件(状态: 整数, 事件名: 字符串, 载荷JSON: 字符串) : 整数 {
    如果 (字符串::等于(事件名, "提问") == 1) {
        J.设置整数(状态, "思考中", 1);            // 这一帧**立刻**发出去
        变量 问题: 字符串 = 取问题(载荷JSON);       // 闭包里不要碰状态句柄，
        实时异步(状态, "回答", 闭包(): 字符串 {     // 要用的值先取出来捕获进去
            返回 问大模型(问题);                   // 后台协程里跑，三秒也不挡连接
        });
    }
    返回 状态;
}

函数 处理消息(状态: 整数, 消息名: 字符串, 载荷JSON: 字符串) : 整数 {
    // __上线__：连接建好、首帧发完之后框架自动投一条。
    // 在这里开定时器 / 起后台任务（初始状态函数 里还没有邮箱，开不了）
    如果 (字符串::等于(消息名, "__上线__") == 1) { 实时定时(状态, 1000, "滴答", "{}"); }
    如果 (字符串::等于(消息名, "滴答") == 1) {
        J.设置整数(状态, "秒", J.获取整数(状态, "秒") + 1);
        实时定时(状态, 1000, "滴答", "{}");        // 显式续下一拍
    }
    如果 (字符串::等于(消息名, "回答") == 1) {
        变量 错文: 字符串 = 异步错误(载荷JSON);     // 任务抛异常也会投回来
        如果 (字符串::字节长度(错文) == 0) { J.设置字符串(状态, "答", 载荷JSON); }
    }
    返回 状态;
}
```

| 函数 | 作用 | 对标 |
| --- | --- | --- |
| `实时定时(状态, 毫秒, 消息名, 载荷)` | 延迟后投给自己 | `Process.send_after` |
| `实时自投(状态, 消息名, 载荷)` | 立刻投给自己（把一件事拆成几拍） | `send(self(), …)` |
| `实时异步(状态, 消息名, 函数(): 字符串)` | 后台跑，返回值当载荷投回来 | `start_async` |
| `异步错误(载荷)` | 载荷是不是错误信封；是则返回错误文本 | `{:error, …}` 分支 |
| `实时邮箱(状态)` | 取本连接的邮箱句柄（0 = 这条路由没开消息） | —— |

- **定时器不是隐式重复的**：要周期就在收到时再定一次。好处是页面进了「不用再动」
  的状态自然就停了，不需要「取消定时器」这种 API。
- **生命周期**：邮箱随连接生灭。连接断开即关闭，之后所有投递（含排队中的定时器）
  返回 0 并丢弃；邮箱句柄单调递增永不复用，迟到的定时器**绝不会**打进后来那条
  连接的邮箱。「页面关了定时器还在跑」不会发生。
- **代价**：带消息的连接循环每 100ms 醒一次查邮箱（不带消息的路由仍是纯阻塞，
  零开销），也就是定时消息最坏迟 100ms 到。
- 跨连接推送不走这里——「一个人操作，同 topic 所有人都更新」用下面的 `频道广播`。
- 完整示例见 `examples/实时_时钟与异步.qi`（秒表 + 2 秒慢任务，慢任务跑的时候
  秒表照走）。

### 上传（进度 / 校验 / 取消）

传统 multipart POST 传的时候页面什么都干不了：没有进度、不能取消、传到一半失败
只能整个重来，而且大小/类型/张数要等文件整个传完才知道。

`上传.qi` 让文件跟着**已有的 WebSocket** 走：客户端切成块一块块送，服务端边收边
落盘，每收一块更新一次进度。进度条就是普通的状态 → HTML，页面上不用写一行脚本。

```qi
// mount 时声明
允许上传(状态, 上传设置("照片", "image/*", 4000000, 3, "上传目录"));

// 模板
HTML {
    <div class="qi-card" data-upload-drop="照片">     <!-- 拖放也走同一条路 -->
        {上传输入(状态, "照片", "选照片，或拖进来")}
        {上传进度(状态, "照片")}
    </div>
    <button data-click="保存" 如果={上传空闲(状态, "照片")}>保存</button>
}

// 事件处理：上传相关的帧先让框架挑走
如果 (上传处理(状态, 事件名, 载荷JSON) == 1) { 返回 状态; }
// 保存时消费（每条是 {id,name,size,done,err,path}）
变量 完成: 字符串 = 上传完成表(状态, "照片");
清空上传(状态, "照片");   // 只清条目，**不删文件**（文件已经归业务了）
```

| 函数 | |
| --- | --- |
| `上传设置(名称, 接受, 最大字节, 最多个数, 目录)` | `接受` 直接给 `<input accept>` |
| `允许上传(状态, 配置)` | mount 时调一次 |
| `上传处理(状态, 事件名, 载荷)` | 返回 1 = 这一帧是上传的 |
| `上传输入 / 上传进度(状态, 组名, …)` | 文件框 / 进度列表 |
| `上传条目表 / 上传完成表(状态, 组名)` | JSON 数组文本 |
| `上传空闲(状态, 组名)` | 没有正在传的条目——提交按钮拿它判 |
| `清空上传(状态, 组名)` | 消费完清条目 |

**安全**：客户端先按限制挡一道（200MB 的文件不该先传完再说太大），服务端**独立
再判一遍**——客户端那道只是体验，不是边界。大小按**实际收到的字节**算（客户端能
谎报 size）。文件名会清洗：`..`、路径分隔符、引号全去掉，落盘名是
「时间戳_编号_清洗后的名字」，上传方决定不了写到哪。accept 的文件名和 MIME 都是
客户端报的、能伪造——那道只挡「选错文件」，真要认内容得读文件头，那是业务的事。

**传输**：WS 文本帧 + base64（多 1/3 字节）。选它是为了复用**已经鉴权过的连接**，
不用另开 HTTP 端点、也不用把 WS 会话和 HTTP 请求对起来。代价是不适合超大文件——
几十 MB 以上建议单开一个直传端点。收完才从临时文件挪到正式位置，中途断了不留半个
正式文件；取消会把半截临时文件一起清掉。

完整示例见 `examples/实时_上传.qi`。

### 表单（校验 / 错误 / 保留输入）

每张表单都要重写同样三件事：校验没过时**把用户填的东西还回去**（不然一个字段
写错整张表白填）、错误挂在**出错的那个字段旁边**、「必填 / 至少 6 位 / 两次密码
一致」这些判断一处一份地抄。`表单.qi` 把这三件事收成一个值。

```qi
函数 校验(表: 表单) : 表单 {
    表 = 校验必填(表, "name", "请填名字");
    表 = 校验最短(表, "pass", 6, "密码至少 6 位");
    表 = 校验相等(表, "pass", "pass2", "两次密码不一样");
    返回 表;
}

HTML {
    <form data-change="校验" data-submit="注册">
        {文本字段(表, "name", "名字")}
        {密码字段(表, "pass", "密码")}
        {密码字段(表, "pass2", "再打一遍")}
        <button type="submit">注册</button>
    </form>
}

// 事件处理里
存表单(状态, 校验(动过(表单载入(取表单(状态), 载荷JSON))));
变量 表: 表单 = 校验(动过(表单载入(取表单(状态), 载荷JSON)));
如果 (表单有错(表) == 0) { …真正去注册… }
```

`data-change` 是**表单级**的：里面任何字段一变就把整张表送上来（校验常要看全表，
比如两次密码是否一致），默认防抖 200ms（`data-debounce` 可调）。

| 校验 | |
| --- | --- |
| `校验必填(表, 字段, 提示)` | 去空白后为空就报 |
| `校验最短 / 校验最长(表, 字段, 字符数, 提示)` | 按**字符数**不是字节数——4 个汉字按字节算有 12 |
| `校验相等(表, 甲, 乙, 提示)` | 错误挂在**第二个**字段（用户在那儿打错的） |
| `校验匹配(表, 字段, 正则, 提示)` | 空值不报（交给必填） |
| `校验整数范围(表, 字段, 下限, 上限, 提示)` | |

每个字段只留**第一条**错误——一次糊三条上去用户只会看第一条。

| 渲染 | |
| --- | --- |
| `文本字段 / 密码字段 / 邮箱字段 / 数字字段 / 多行字段(表, 字段, 标签)` | 标签 + 输入框 + 错误，一次给齐 |
| `错误块(表, 字段)` | 自己排版时单独用 |

**「动过」是干什么的**：一进页面就把「请填名字」红字糊到用户脸上很讨厌，所以
错误只有在 `动过(表)` 之后才**渲染**出来（校验本身照常跑，`表单有错` 一直准）。

**错误在 `表单载入` 时清空**：错误是从值推出来的，值变了就得整套重算。不清的话
用户把邮箱改对了「请填邮箱」还红在那儿——这个坑写示例时当场踩过一次，单看代码
完全合理，只有在浏览器里连着改几个字段才看得出来。

完整示例见 `examples/实时_表单校验.qi`。

### 轻路由（live_patch / handle_params）

标签页、筛选、翻页、点开详情——这些都该改 URL（能收藏、能分享、后退键要管用），
但**不该重建连接**。以前只能 `指令_跳转`：整页刷新 + 新 WS + 状态和滚动位置全丢。
切个标签页而已，代价太大。

`实时参数.qi` 让 URL 变化走一条轻路：客户端 pushState 改地址栏，把新 URL 发给
服务端；服务端在**同一个状态**上跑一遍 `参数处理函数`、重渲、回一帧。

```qi
应用值 = 实时块路由带参数(应用值, "/board", 初始状态, 渲染, 处理事件, 处理参数);

函数 处理参数(状态: 整数, 路径: 字符串, 查询JSON: 字符串) : 整数 {
    J.设置字符串(状态, "标签页", 取查询(查询JSON, "tab"));
    J.设置整数(状态, "页码", 取查询整数(查询JSON, "page", 1));
    返回 状态;
}

HTML { <a data-patch="?tab=已完成" href="?tab=已完成">已完成</a> }
```

`data-patch` 写目标 URL（相对绝对都行）。同时写 `href` 是为了右键新开标签页、
以及禁用 JS 时还能用——客户端会 `preventDefault` 走轻路。

`参数处理函数` 在这些时候被调用：**首屏 GET**（服务端按真实 URL 直出，所以直接
打开 `/board?tab=已完成` 不会先渲一遍默认标签页再跳）、WS 连上后客户端报一次、
点了 `data-patch`、浏览器前进后退、服务端 `实时指令(状态, 指令_跳转参数("?tab=x"))`。

查询值一律是**字符串**（URL 里本来就没有类型），要数字用 `取查询整数`。

**边界**：这是 live_patch 不是 live_navigate——patch 目标必须还是**这个页面**
（同一套初始状态/渲染/事件处理）。换页面用 `指令_跳转` 整页走。路径本身可以变
（`/board/7`，路由写成 `/board/:id`），`参数处理函数` 拿得到新路径。

完整示例见 `examples/实时_轻路由.qi`（三个标签页 + 翻页 + 后退键 + 服务端
push_patch；页面上那个「本连接换过 N 次 URL」只增不减，证明连接从头到尾是同一条）。

### 客户端动作（JS commands）

展开折叠、高亮闪一下、聚焦输入框——这类**纯视觉**交互服务端根本不需要知道。
以前只有两条路：走 `data-click` 往返一次（白跑一趟还要等网络），或者自己写 JS
（于是「不用写前端」这句话就不成立了）。`客户端动作.qi` 给一组声明式操作，
写进属性，客户端当场跑完。

```qi
变量 展开: 动作 = 切类(新动作(), "#详情", "open");
展开 = 切类(展开, "#箭头", "转90");
展开 = 聚焦(展开, "#搜索框");

HTML {
    <button data-js-click={动作值(展开)}>展开</button>
    <div id="详情" class="fold" data-js-keep>…</div>
}
```

| 函数 | 作用 |
| --- | --- |
| `切换显隐 / 显示 / 隐藏(动作, 选择器)` | 内联 display，不依赖 CSS 类 |
| `加类 / 去类 / 切类(动作, 选择器, 类名)` | 类名可写多个，空格分开 |
| `闪一下(动作, 选择器, 类名, 毫秒)` | 加上类，到点自己去掉 |
| `设属性 / 删属性(动作, 选择器, …)` | 属性 |
| `聚焦 / 滚动到(动作, 选择器)` | |
| `派发事件(动作, 选择器, 事件名, 载荷JSON)` | 冒泡 CustomEvent，第三方挂件接得到 |
| `动作值(动作)` | → 属性值 |

**选择器留空 = 触发的那个元素**：`切类(新动作(), "", "选中")`。

想让服务端也知道，在同一个元素上照常写 `data-click`——两件事各做各的，客户端
立刻生效，服务端那趟该多久还是多久。服务端反过来也能下发：
`实时指令(状态, 指令_动作(闪一下(新动作(), "#行7", "hit", 600)))`。

**⚠ 下一帧可能把改动冲掉。** 这些操作改的是 DOM，而 morph 会把 class / style
同步回**服务端渲染的版本**——展开的菜单会在下一帧莫名其妙合上，哪怕那一帧跟
菜单毫无关系（一个定时器滴答就够了）。要跨帧存活，在那个元素上写
`data-js-keep`：morph 就不再管它的 class 和 style。代价是服务端也改不动这两项，
这个元素的外观整个交给客户端。真需要服务端控制的状态，还是放服务端。

完整示例见 `examples/实时_客户端动作.qi`（页面上有个每秒跳的计数，专门用来看
「帧一直在来」时哪些改动活得下来、哪些活不下来）。

### 实时组件（LiveComponent）

页面一大，`事件处理函数` 就变成几十个分支的 if 链，各部件的状态键平铺在同一个
JSON 对象里，改一处要通读全部。`实时组件.qi` 把状态和事件按部件切开。

「只重渲这棵子树」**不用组件也已经成立**——结构化 diff 会算出没变的子块一个
字节都不发。组件补的是另外两样：**状态隔离**和**事件路由**。

```qi
函数 计数器() : 实时组件 {
    返回 创建组件("counter", 计数器初始, 计数器渲染, 计数器处理);
}

// 页面模板里插一个
函数 渲染(状态: 整数) : HTML块 {
    返回 HTML { <div><h1>首页</h1>{渲染组件(状态, 计数器())}</div> };
}

// 页面的事件处理开头先让组件挑走属于它们的
函数 处理事件(状态: 整数, 事件名: 字符串, 载荷: 字符串) : 整数 {
    如果 (组件事件(状态, 计数器(), 事件名, 载荷) == 1) { 返回 状态; }
    …页面自己的事件…
    返回 状态;
}
```

`渲染组件` 给子树套一层 `<div data-target="组件id">`；客户端上行时往上找最近的
`[data-target]`，把它放进载荷的保留键 `__target__`。所以**页面和组件用同名事件
也不会串**（两处都叫「清零」，各清各的）。组件状态存在页面状态的
`__组件__<id>` 键下，按需创建，随连接释放。

同一份组件代码可以开多个实例（不同 id）——点其中一个，另一个连字节都不下发。

### 实时流（Streams）

结构化 diff 已经让「列表改一项」只发那一项，但前提是**服务端每帧都得把整个
列表重渲一遍**才能比对。聊天记录、日志、通知这类只增不改、能到几千条的列表，
这一步本身就是负担，而且服务端得一直端着整份列表。

`实时流.qi` 反过来：服务端**不留列表**，只说「加了这一条」「删了那一条」。

```qi
// 容器要有 id，并且 data-ignore 把它挡在整页 morph 之外 ——
// 流进去的项在页面模板里根本不存在，不挡住的话下次整页重渲会全抹掉
函数 渲染(状态: 整数) : HTML块 {
    返回 HTML { <div><h1>聊天</h1><ul id="msgs" data-ignore></ul></div> };
}

函数 处理事件(状态: 整数, 事件名: 字符串, 载荷: 字符串) : 整数 {
    如果 (字符串::等于(事件名, "发言") == 1) {
        变量 id: 字符串 = 下一个消息id();
        流追加(状态, "msgs", id, HTML { <li data-key={id}>{取文本(载荷)}</li> });
        实时指令(状态, 指令_滚动("#msgs"));
    }
    返回 状态;
}
```

状态里一条消息都不用存。四个操作：

| 函数 | 作用 | 对标 |
| --- | --- | --- |
| `流追加(状态, 容器id, 键, 块)` | 末尾加；键已存在则原地替换（也用来「更新某条」） | `stream_insert` |
| `流前插(状态, 容器id, 键, 块)` | 开头加；键已存在则移到开头并替换 | `stream_insert(at: 0)` |
| `流删除(状态, 容器id, 键)` | 按键删一项 | `stream_delete` |
| `流清空(状态, 容器id)` | 整个容器清掉 | `stream(reset: true)` |

键就是项的 `data-key`，必须是跟着数据走的稳定 id。

**什么时候不该用流**：列表项内部的字段会跟着状态变（每项有个「已完成」勾选框），
还是用 `对于={}` + 结构化 diff——那条路服务端知道每项长什么样，改一个字段只发
一个槽位。流适合「一条进来就基本不动」的场景。

完整示例见 `examples/实时_组件与流.qi`（两个计数器组件 + 一条消息流）。

### 实时广播（PubSub / 跨连接共享）

`实时广播.qi` 让同一 topic 的所有连接共享状态并互相广播（`共享WS路由`）。
v2 新增**广播频道句柄**（对标 `Phoenix.PubSub.broadcast`）——服务端任意位置
（定时任务、LLM 回调、HTTP handler）都能主动推：

```qi
变量 频道: 整数 = 创建广播频道();
应用值 = 共享WS路由带频道(应用值, "/board/ws", 频道, 准入, 渲染, 处理);
// 任意 goroutine 里：
频道广播(频道, topic, 渲染(topic));           // 主动推重渲染
频道指令(频道, topic, 指令_标题("有新消息"));  // 主动推浏览器指令
变量 在线: 整数 = 频道在线数(频道, topic);     // 简易 Presence
```

老 `共享WS路由` 签名不变（内部自建频道）；客户端运行时与实时页面完全同一份，
心跳已降级为可选保活（`共享实时脚本` 第三参传 30000 或 0 关闭）。

## RPC（Connect 协议）

`RPC.qi` 实现 [Connect 协议](https://connectrpc.com) 的**一元调用 + JSON 编码**
——connect-go / connect-es / buf curl 等 gRPC 生态客户端可直连，普通 curl 也能打。
**不是 protobuf 线格式**；protobuf 编码与流式 RPC 属后续。

```qi
函数 说你好(上下文值: 上下文, 请求JSON: 字符串) : 字符串 {
    变量 请求对象: 整数 = J.解码(请求JSON);
    变量 名字: 字符串 = J.获取字符串(请求对象, "name");
    J.删除(请求对象);
    如果 (字符串::字节长度(名字) == 0) {
        返回 RPC错误("invalid_argument", "name 字段不能为空");   // → 400 + Connect 错误 JSON
    }
    返回 "{\"greeting\":\"你好, " + 名字 + "!\"}";
}

应用值 = 注册RPC(应用值, "greet.GreeterService", "SayHello", 说你好);
// 挂载 POST /greet.GreeterService/SayHello（服务名/方法名用 ASCII）
```

```bash
curl -X POST http://127.0.0.1:7429/greet.GreeterService/SayHello \
     -H "Content-Type: application/json" -d '{"name":"世界"}'
# {"greeting":"你好, 世界!"}
```

- 错误按 Connect 规范返回 `{"code":"...","message":"..."}` + 对应 HTTP 状态
  （invalid_argument→400、unauthenticated→401、permission_denied→403、
  not_found→404、already_exists→409、resource_exhausted→429、
  unimplemented→501、unavailable→503、internal→500 等）。
- 处理函数用 `RPC错误(错误码, 消息)` 生成错误返回值，正常路径直接返回响应 JSON。
- `connect-protocol-version: 1` 请求头按规范忽略；`application/proto` 请求回 415。
- 完整示例（含错误路径）见 `examples/rpc_问候.qi`。

## 现在的取舍

当前版本优先把下面这条链路做稳：

`应用(持有 handler 值 + 路由树) -> 路由注册 -> 请求解析 -> 匹配 -> middleware -> handler -> 响应输出`

当前路由树已经具备这些行为：

- 注册时建树，不是线性追加
- 匹配时沿树下降，不是全表扫描
- 静态段优先于参数段
- 节点 / handler / middleware 存储已经改成动态列表
- 单节点静态子边已经改成动态列表，不再固定 8 槽
- 支持 `HEAD`
- 支持 `OPTIONS`
- 没有显式 `OPTIONS` 处理器时，自动返回 `Allow`
- 重复注册同一路径同方法会报冲突

也就是说，先把内核做实，再往上叠：

- 控制器
- 分组路由
- 更自动的参数提取
- 更完整的一等函数处理器（当前已支持第一版）

## 请求提取

现在除了 `路径参数 / 查询参数 / 请求主体`，也已经有这些入口：

```qi
变量 内容类型文本: 字符串 = 请求头(上下文值, "Content-Type");
变量 表单页码: 整数 = 表单整数(上下文值, "page", 1);
变量 JSON对象: 整数 = 解析JSON主体(上下文值);
变量 用户名: 字符串 = JSON字符串字段(上下文值, "name");
```

如果你自己拿 `解析JSON主体(上下文值)` 的结果继续往下用，记得在用完后调用 `JSON.删除(...)`。

## 运行应用

完整服务器入口现在可以直接写成：

```qi
变量 应用值: 应用 = 创建应用();
应用值 = 配置(应用值, "127.0.0.1", 3076);
应用值 = 获取(应用值, "/", 首页处理);
运行应用(应用值);
```
